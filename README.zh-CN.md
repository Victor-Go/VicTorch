# VicTorch

[English](README.md) | 简体中文

屏幕到摄像头的光学文件传输。发送端把文件编码成一串连续变化的网格码显示在屏幕上，接收端用摄像头录像并逐帧解码，还原出原文件。

纯前端、无后端、无网络请求，数据不会离开你的设备；页面不保存任何内容，不使用 Cookie 或本地存储。

## 使用

1. **速率检测（可选）**：发送端打开“速率检测”并点击开始，接收端对准屏幕、打开摄像头，会自动进入检测模式。约 30 秒后接收端给出推荐的帧率、密度、颜色和纠错比例。
2. **发送**：选择文件，把推荐配置手动填到发送端，点击开始发送。“全屏显示”是开始按钮下方的选项，开始后不可更改。
3. **接收**：打开摄像头并对准发送端屏幕，收齐后校验整文件 CRC32，通过才提供下载。

提示：

- 摄像头需要 HTTPS 或 localhost，部署到 GitHub Pages 即满足。
- 发送不会自动停止：达到计划帧数后会继续发送新的编码帧，直到你点击停止，所以少量损坏的帧不会导致重发。纠错比例只决定计划帧数，用于进度条和时间估算。
- 传输单向，发送端无法得知接收结果。
- 界面语言跟随浏览器（英文或简体中文，其余回退到英文），也可在右上角切换。

## 原理概要

- 自定义网格码：密度 32–128、每格 2/4/8/16 色、四角定位标记、校准色带、每帧 CRC32。
- LT 喷泉码（鲁棒孤子分布）+ peeling 解码，抗丢帧、乱序和重复。
- 速率检测由低到高逐级加压，按 85% 成功率阈值推荐配置。

详细契约见 [docs/](docs/)，模块与约定见 [AGENTS.md](AGENTS.md)。

## 开发

```bash
npm install
npm run dev        # 开发服务器（localhost 可用摄像头）
npm test
npm run build      # 产物在 dist/，纯静态
```

推送到 `main` 后，GitHub Actions 会测试、构建并发布到 GitHub Pages（仓库 Settings → Pages → Source 选 “GitHub Actions”）。
